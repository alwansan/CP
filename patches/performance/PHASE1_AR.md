# PATCH275 — المرحلة الأولى من تحسين سلاسة الواجهات

**المصدر:** `feature/local-account` عند `82d7f67037f67659115d41782d3a9b5bf4e0bd02`

**فرع العمل:** `feature/ui-performance-optimization`، مستقل تماماً ولا يُدمج تلقائياً مع `main` أو فرع المصدر.

## التشخيص الثابت من ملفات المشروع

| الموضع | الملاحظة في المصدر | الإصلاح |
|---|---|---|
| `res/layout/fragment_home.xml` | قائمة الشاشة الرئيسية `RecyclerView` بارتفاع `wrap_content` وقيد علوي فقط؛ تخطيط غير محدود أثناء قياس قائمة طويلة | ارتفاع 0dp مع قيد أعلى وأسفل حدود الشاشة |
| `res/layout/fragment_franchises.xml` | قائمة شبكية عمودية `wrap_content` وتحريك `animateLayoutChanges=true` | ارتفاع محدد بقيود الشاشة وإيقاف تخطيط متحرك تلقائياً |
| `item_base_video*.xml` و`horizontal_scroll_videos_layout.xml` و`item_slider.xml` | عناوين بطاقات كثيرة تتكرر فيها `marquee_forever`، وبعضها يطلب التركيز؛ كل عنوان متحرك يمكن أن يسبب رسم إطارات مستمراً | النص القصير أو الطويل يعرض بثبات مع `ellipsize=end` دون حركة دائمة |
| `item_base_video*.xml` | انتقال صور Fresco مدته 800ms لكل بطاقة ظاهرة | خُفّض إلى 120ms لتقليل تداخل مؤثرات الشفافية أثناء التمرير السريع |
| `LocalRuntime.observeEpisodes` | تحويل مجموعة حلقات كاملة إلى JSON قبل جدولة العمل على الخلفية، وبالتالي يجري التحويل على خيط استدعاء النتيجة | نُقل `JSON.i(value)` و`JSONArray` إلى `NETWORK` دون تغيير شروط الفحص أو البيانات |
| `LocalRuntime.decorate` | استخراج معرفات 3 عناصر موارد بالاسم في كل `OnLayoutChange` لصفحة الملف الشخصي | استخراج المعرفات مرة واحدة عند إنشاء المستمع |

هذه **مواطن تكلفة مثبتة في الكود** وليست قياساً مؤكداً لمقدار التقطيع الفعلي. لا يمكن الجزم أن أي واحدة منها وحدها تسبب كل التأخير دون trace من الهاتف.

## حدود التعديل

لم نوقف تحديثات الاشتراكات أو الإشعارات أو متابعة المشاهدة أو الطلبات الأساسية ولم نبدل مصادر الصور. التغييرات تختص بقياس القوائم والرسم والمزامنة مع الـ UI. بقاء السلاسة يجب فحصه على APK مركب على هاتف حقيقي.

## اختبارات البناء

يشغّل `.github/workflows/local-account.yml` عند دفع فرع الأداء فقط الاختبارات السابقة، واختبار `scripts/check_ui_performance.py`، ثم تجميع Smali المتولّد من مصدر Java، وبناء APK وتوقيعه والتحقق منه. يُنشئ Release تجريبياً منفصلاً باسم `ui-performance-PATCH275-...`، والملف المباشر `Cinemana_UI_Performance_PATCH275_signed.apk`. نشر الإصدار مشروط بنجاح كل المراحل.

## مرحلة القياس التالية

لتحويل الاحتمالات إلى سبب محدد، قارن قبل وبعد تحت نفس الشبكة ونفس سلوك الشاشة:

1. ابدأ التطبيق بحالة مستقرة ثم نفّذ تمريراً سريعاً للأسفل والأعلى عدة مرات؛ سجل طول كل تجميد وسلاسة ظهور الصور.
2. افتح تفاصيل عمل، ارجع إلى الرئيسية، ثم انتقل بين البحث والتصنيفات والملف الشخصي.
3. عبر Android Debug Bridge شغّل قبل الاختبار:
   `adb shell dumpsys gfxinfo com.cinemana.pro reset`
   وبعده:
   `adb shell dumpsys gfxinfo com.cinemana.pro framestats`
4. جمع `Perfetto` / `System Trace` مع `Frame Timeline` و`Main Thread` و`RenderThread` و`CPU scheduling` لمعرفة أثر `measure/layout` و`draw` و`binder` و`image decode`.
5. في مرحلة لاحقة افحص `HomeItems` و adapters والتحديثات المتكررة `notifyDataSetChanged` ومخازن صور Fresco ومدى استعادة الـ fragments قبل أي تغيير معماري كبير.

**معيار النجاح المقترح:** انخفاض الـ janky frames وزمن الإطارات فوق ميزانية العرض، بدون اختفاء عناصر أو فقدان بيانات أو كسر تحميل الصور. لا توجد حتى الآن أرقام FPS موثقة من جهاز المستخدم.
