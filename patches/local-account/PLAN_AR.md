# الحساب المحلي — خريطة التنفيذ وحالة العمل

الأساس: fix/download-mkv-self-repair عند 06ec99add982ace4b35898f763b31ec532a5a7e5 (PATCH265).
الفرع الجديد: feature/local-account.
هذا عمل قيد التنفيذ. لا توجد نسخة APK محلية مكتملة في هذا التغيير.

## نتيجة قراءة الجلسة السابقة

قرئت الرسائل المعروضة في رابط 6ae1d894-aef4-83eb-b1cc-bca6211262b8. التجربة القديمة عدلت isLoggedIn وتدفق حالة الدخول، ثم اصطدمت بـ VerifyError في CinemanaApplication.e(String)، وبعد تصحيحه بـ Account does not exist عند retrieveAccount/AuthorizationInterceptor. الإصلاح اللاحق جعل قراءة الحساب اختيارية، لكنه لا يثبت تحويل مصادر القوائم إلى محلية. لن نعيد أسلوب فتح الحالة العامة للتطبيق قبل فصل كل مستهلك لها عن المصادقة.

اقتراح C2 في الجلسة يستخدم allVideoInfo/id/{videoNb} وvideoSeason/id/{rootEpisodeId}. وجود الواجهات في الكود لا يثبت إمكانية الوصول الحي بدون حساب. لا تُستخدم تواريخ نشر أو أرقام حلقات فقط لمنع التكرار؛ المفتاح هو هوية الحلقة الأصلية مع هوية العمل.

## التخزين

نواة LocalAccountStore موجودة كمصدر Java قابل للاختبار داخل patches/local-account/src. تخزن الاسم والصورة وقوائم المفضلة/لاحقاً/المشاهَد/الاشتراكات وموضع التقدم وسجل معرّفات الحلقات وصندوق التنبيهات. الملف account.bin بإصدار schema صريح، ولا يحتوي أي اعتماد حساب شبكي. الكتابة pending ثم استبدال ذري، ولا يتغير state بالذاكرة عند فشل التخزين.

هذه النواة ليست مربوطة بالتطبيق بعد. لا نعتبر وجود كود خارج مجلد app ميزة منشورة. تستخدم حالياً java.nio.file للاختبار؛ قبل إدخالها إلى DEX يجب استبدال adapter الملفات بـ Android AtomicFile لدعم أجهزة minSdk الحالية، أو إثبات توافقها مع API المستهدف. يلزم executor متسلسل واحد ونسخة واحدة لكل عملية؛ لا تُستعمل على UI thread.

يفضل تخزين المصدر الأساسي داخل filesDir/data/local-account حتى لا يُعدّل من تطبيقات أخرى. المسار النهائي يتوافق مع طلب المستخدم لبيانات data عبر نسخة التصدير/المرآة المتفق عليها. لا نغيّر صيغة ملفات Portable123 الحالية أو نمس تنزيلات الفيديو.

## النسخ الاحتياطي

النواة تصدر account.bin داخل ZIP وتستورد فقط هذا الإدخال؛ ترفض المسارات الغريبة والمكررة والبيانات المبتورة وschema غير معروف والملفات المتضخمة. تتحقق من الأرشيف كاملاً قبل تعديل الحساب. تعيد تأسيس baseline التنبيهات بعد الاستيراد لمنع إشعارات الحلقات القديمة، وتحافظ على صندوق التنبيهات المستورد.

المتبقي في Android: ACTION_OPEN_DOCUMENT_TREE لاختيار مجلد التصدير ثم DocumentsContract لإنشاء الملف، وACTION_OPEN_DOCUMENT للاستيراد، وقراءة/كتابة streams خارج الواجهة؛ رسائل نجاح/فشل، تحديث القوائم بعد commit، ومراجعة عدم بقاء مراجع حية قديمة. لا تُصدَّر ملفات الفيديو أو توكنات/كوكيز أو ملفات التفضيلات العامة التي قد تحتوي أسراراً.

واجهة الصورة تحتاج اختيار صورة ثم فك بحجم مقيد وإعادة ترميزها محلياً، لا حفظ URI مؤقت يزول الإذن عنه. حد النواة 2 MiB للصورة، لكن التحقق من النوع/الأبعاد يقع على Android adapter ولم يُنفذ بعد.

## الإشعارات الخفيفة

النواة تطبق baseline في أول رد حلقات كامل ناجح بعد الاشتراك. لا تولّد إشعاراً في أول رد أو من رد فارغ. تجمع المعرفات المعروفة ولا تحذفها إذا اختفت حلقة مؤقتاً، وتسجل الحلقة الجديدة في inbox مرة واحدة. إلغاء الاشتراك يوقف reconciliation لذلك العمل. إعادة الاشتراك تؤسس baseline جديداً، مع الاحتفاظ بسجل التنبيهات السابق لمنع التكرار.

المتبقي: عامل WorkManager فريد مع شرط اتصال، فاصل مبدئي متحفظ (مثلاً 6 ساعات، ليس وعداً بوقت دقيق)، فحص عند فتح التطبيق بشرط عمر آخر فحص ومنع التداخل، عمل واحد في المرة، حدود طلبات ودوران عادل بين الاشتراكات، مهلات ونكوص عند فشل الخادم. لا polling كل دقيقة ولا wake lock دائم ولا خدمة دائمة.

يجب التأكد من اكتمال/ترقيم صفحات قائمة الحلقات قبل reconcile. فشل الشبكة لا يبدل baseline. العامل لا يحمل الصور أو الفيديو. يلزم سجل outbox/تأكيد تسليم للإشعار كي لا يضيع بين حفظ inbox وتعطل العملية، ومعرّف إشعار ثابت لمنع تكرار العرض بعد إعادة المحاولة. إذن POST_NOTIFICATIONS وفتح الحلقة بالموجّه الحالي يُربطان لاحقاً. إعادة استخدام شكل قائمة الإشعارات ممكن، ولا يعني إعادة استخدام تسجيل OneSignal المرتبط بالحساب.

## اللوق

النواة تستدعي Events بأسماء أحداث ثابتة وأعداد فقط: profile_saved، list_saved، list_removed، episodes_reconciled، backup_exported، backup_imported. لا تسجل أسماء الأشخاص أو بيانات الصورة. المتبقي adapter إلى Log94/diagnostics الحالي، مع حالات فشل الاستيراد والتخزين وحالة baseline ونتائج HTTP ونقاط تحديث الواجهة، دون body أو authorization.
