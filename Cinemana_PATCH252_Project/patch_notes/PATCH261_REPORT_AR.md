# PATCH261 — استرداد MP4 مرتب حسب الأقدمية

الفرع الأساسي: `fix/download-mkv-self-repair` عند `3811de0f`.

## التشخيص

- سجل CL أظهر مرور الإصلاح على 19 ملف MP4 دون قبول أي ملف، مع سبب عام لا يميز أخطاء الربط.
- المستدعي يستخدم `onRecoveredVideo`, `matchesDiskSourceOrOutput`, `matchesDiskOutputPath` دون تعريفها في MkvExporter. apktool لا يكتشف غياب الدوال.
- عدة دوال مساعدة تستدعى من حزمة features بينما صلاحيتها محلية لحزمة ca1.
- مسارات DAO احتوت receiver خاطئا/وسيط context مفقودا، وإرجاع Object بلا تحويل إلى CinemanaDownloadItem.
- JSON الحلقة E47 في CL يشير إلى ملف SRT كمصدر: callback الترجمة يستطيع تلويث سجل الفيديو المشترك.

## السلوك بعد التعديل

- الزر وFileObserver يستعملان نفس المرور المتسلسل على الملفات المباشرة في Cinemana/work. الفرز حسب آخر تعديل ثم الاسم عند تساوي الوقت.
- كل MP4 نهائي يمر للمطابقة والتحقق فورا قبل الانتقال للملف التالي. لا ينتظر انتهاء جميع التنزيلات. ملفات mp4.temp ومؤقتات remux لا تحول.
- إرسال الملف الفعلي إلى عامل الاسترداد؛ مشاركة قفل ومفتاح المهمة مع طابور MKV الأصلي، مع تخطي المهمة الموجودة فيه. تبقى موارد التحويل وحدود FFmpeg الأصلية.
- أحداث الملفات تطلب فحصا مؤجلا 250ms؛ تجمع الأحداث المتكررة في طلب واحد. يعاد التدقيق كل خمس ثوان مع بقاء MP4/temp أو jobs، ويتوقف المؤقت عند خلوها. يبقى FileObserver ساكنا لاستقبال العمل الجديد. لا يوجد polling دائم عند الخمول.
- الزر لا يقرأ اللوغات ولا يمسح سجل جميع طلبات التنزيل. الاستعادة الأصلية باقية، وقراءة JSON المتوقف عند بدء التطبيق تحصل مرة بعد المرور السريع.
- إصلاح الوصول والربط المفقود، واستخدام ذاكرة العناصر التي حلت هويتها. تعاد مراجعة نية الحذف/الإيقاف قبل إدراج التحويل وعند بدء العامل.
- callbacks الترجمة لا تكتب JSON الفيديو. يبقى JSON خارج الحاوية؛ metadata البسيطة في التصدير الأصلي باقية.
- تنظيف الحلقة عند الحذف يستعمل المسار المحفوظ قبل حذف الصف وملفات proof المحلية، حتى إذا حذف JSON بعد نجاح المهمة. لا تنظف بيانات حلقة أخرى، ولا يلمس فحص الإصلاح ملفات المكتبة خارج work.
- لا تعد نسخة MKV موجودة بحجم كبير وحده إثبات اكتمال؛ يلزم إثبات الترقية بالمسار والحجم قبل تنظيف المصدر وJSON.

## التحقق والحدود

- فحص مستقل لتعريف الدوال المستدعاة وصلاحياتها، labels، وسجلات invoke، ونطاق الزر، وجدولة الخمول.
- خمسة اختبارات تنفذ تعليمات تدفق Smali الخاصة بالجدولة والمسح بمحاكاة filesystem/scheduler: دمج الأحداث، التوقف بالخمول، الاستيقاظ لاحقا، استمرار العمل ثم التوقف، واستبعاد temp/الترجمات وفرز MP4.
- تجميع apktool الكامل محليا. البناء والتوقيع في GitHub Actions مطلوبان للإصدار.
- هذه الفحوص ليست تحقق أنواع ART ولا تجربة هاتف. يجب اختبار: تنزيل متعدد مع إغلاق/فتح التطبيق، تحويل دون ضغط الزر، عدم تكرار job، وحذف حلقة بعد اكتمالها مع مراجعة بيانات رمزها فقط.
- الملفات القديمة دون هوية DB/خطة ترجمة موثوقة تبقى مؤجلة؛ لا تخترع هوية أو روابط ولا تحول لمجرد تشابه الاسم.
