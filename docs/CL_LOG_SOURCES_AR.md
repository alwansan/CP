# خريطة مصادر سجلات Cinemana في CL

**فحص مباشر:** 2026-11-09. المستودع https://github.com/alwansan/CL على الفرع `main`.

## ماذا وجدنا فعلياً؟
- `https://github.com/alwansan/CL/tree/main/log`: يوجد ملف واحد فقط باسم `tree.txt` وقت الفحص. هذا **فهرس مسارات محلية** يصف `/storage/emulated/0/Cinemana/`، وليس رفعاً فعلياً لكل الملفات المذكورة.
- `https://github.com/alwansan/CL/tree/main/data`: المسار غير موجود (404) وقت الفحص.
- `https://github.com/alwansan/CL/tree/main/Clog`: المسار غير موجود (404) وقت الفحص.
- وجود `raft log/` و`test/` داخل CL لا يجعلهما تلقائياً سجلات Cinemana؛ لا تخلطهما.

## أنواع الملفات التي *يشير إليها* فهرس هاتف المالك
| الفئة | أسماء ظهرت في tree.txt | استخدام استكشافي |
|---|---|---|
| التنزيلات | `downloads.log`, `load_diagnostics.filedownloader.jsonl`, `download_repair_actions.log` | طابور التنزيل، إعادة المحاولة، الاستعادة |
| MKV | `.mkv_export.log`, `mkv_repair_pending.properties`, `mkv_identity.map`, `mkv-proofs/` | المطابقة بين ملف الوسائط والسجلات والترقية |
| المشغل | `player_diagnostics.log`, `.mkv_player_resolver.log`, `.mkv_subtitle_catalog.log` | BUFFERING/High10/Surface/ترجمات |
| UI والأداء | `ui95.log`, `ui_performance.jsonl` | أخطاء الواجهة والتجميد والأداء |
| شامل | `diagnostics.log`, `ca1_batch.jsonl`, `load_diagnostics.main.jsonl` | تسلسل الأحداث والتوقيت |
| استعادة | `data/cnm_recovery/` وملفات JSON محلية | جرد الفهرس فقط؛ ليست قاعدة بيانات للاختبار |

**مهم:** هذه أسماء ملفات في الفهرس المحلي، لا يعني وجود محتواها في CL. قد تتغير الأسماء حسب إصدار التطبيق أو طريقة الرفع.

## سياسة جمع الأدلة
1. اختر حالة واحدة قابلة للتكرار (مثال: استئناف تنزيل، تحويل MKV، تبديل جودة، تغيير ترجمة).
2. سجّل وقت بداية التجربة والمنطقة الزمنية، إصدار APK/commit SHA، الإجراءات الفعلية، النتيجة المتوقعة والفعلية، ووقت نهاية التجربة.
3. قدّم السجلات المتعلقة بالفترة نفسها قبل/أثناء/بعد العطل. اجمع Logcat عند وجود crash أو ANR، مع thread/process/stack إن تيسر.
4. لا تحذف الملف النهائي أو `.part`، ولا تمسح بيانات التطبيق لمجرد جعل الحالة نظيفة.
5. عند رفع الأدلة إلى CL، أشر إلى المسارات الموجودة فعلاً والـcommit؛ لا نستنتج أسماء الملفات من tree.txt فقط.
6. افصل بيانات الفحص التشخيصي عن بيانات المستخدم، واختبر تغييرات Room على نسخ مصطنعة.

## الخصوصية
قد تتضمن السجلات روابط بث موقعة، أسماء عناصر، ملفات شخصية أو معرفات جلسات. قبل أي commit عام **نقّح العناوين الحساسة والرموز وعناوين URL الخاصة**. لا ترفع قاعدة بيانات خاماً أو مفاتيح توقيع أو token خاصاً على GitHub عام. إذا احتجنا ملفاً خاماً لإثبات حادثة، استخدم مساراً خاصاً وآمناً.

## ماذا نفعل فور وصول ملفات جديدة؟
أعد فحص شجرة CL الحية وتواريخ الملفات، ثم ضع فهرساً بالأدلة في `memory/sessions/`، واستخرج أول خطأ مؤثر ومتسلسل زمنياً، وقارنه بنسخة التطبيق المختبرة. لا تنقل فرضية من فهرس أسماء إلى حكم سببي.
