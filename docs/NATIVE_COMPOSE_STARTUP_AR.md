## Candidate route
Prefer isolated minimal Application class chosen only when requested original class EXACT, fixed known package EXACT and Application.getProcessName() == package+:nativeui on API28+. Subclass existing CoreComponentFactory and delegate original superclass for all other cases; no Intent/extra controls. On old API or unknown process preserve legacy, do not launch native Activity. Minimal Application checks actual base package/role again on attach; no original class inheritance, no Dagger, no original app getters. This avoids bypassing invoke-super or leaving inherited configuration callback and lazy DI incomplete. Factory must not call Context APIs before attach. Must verify process name availability and actual class instantiated on ART; if null/unavailable do not replace. Manifest providers, resources, AndroidX duplicate binary compatibility and class loading still need audit and signed original gate. Never use this as proof of original integration.
