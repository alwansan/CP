## Verified existing original startup, static audit
- Manifest names com.shabakaty.cinemana.CinemanaApplication and androidx.core.app.CoreComponentFactory. Existing :filedownloader must remain untouched. WorkManagerInitializer is disabled, but ProcessLifecycleOwnerInitializer is enabled (no enabled=false) and multiprocess=true: correct historical docs that implied both disabled. Lifecycle provider onCreate obtains Application, registers lifecycle callbacks, initializes lifecycle Handler; it does not cast to CinemanaApplication in inspected body. Actual provider placement remains to be measured, don't assume multiprocess implies or excludes execution in new process.
- CinemanaApplication.attachBaseContext lines 95–155 sets uj2 locale wrapper, t and s and invokes ContextWrapper.attachBaseContext; onCreate lines 529–547 invokes vk0.onCreate (Dagger init), theme and LocalRuntime; Restart108 bootstrap later. g() reads s and throws if absent, onConfigurationChanged reads t and throws if absent. vk0.c() lazily calls b() and injector, not just startup. Guarding only onCreate or skipping legacy attach with unmodified overrides unsafe.
- CoreComponentFactory.smali is non-final; instantiateApplication(ClassLoader,String) delegates AppComponentFactory then unwraps CompatWrapped; other components similarly delegate. Android official API28 AppComponentFactory supports overriding creation of Application object before Context is initialized: https://developer.android.com/reference/android/app/AppComponentFactory#instantiateApplication(java.lang.ClassLoader,%20java.lang.String)
## Candidate route
Prefer isolated minimal Application class chosen only when requested original class EXACT, fixed known package EXACT and Application.getProcessName() == package+:nativeui on API28+. Subclass existing CoreComponentFactory and delegate original superclass for all other cases; no Intent/extra controls. On old API or unknown process preserve legacy, do not launch native Activity. Minimal Application checks actual base package/role again on attach; no original class inheritance, no Dagger, no original app getters. This avoids bypassing invoke-super or leaving inherited configuration callback and lazy DI incomplete. Factory must not call Context APIs before attach. Must verify process name availability and actual class instantiated on ART; if null/unavailable do not replace. Manifest providers, resources, AndroidX duplicate binary compatibility and class loading still need audit and signed original gate. Never use this as proof of original integration.
