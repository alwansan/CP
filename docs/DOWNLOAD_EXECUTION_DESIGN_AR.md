## القرارات المعمارية المقترحة
1. Single logical intent owner في main، native FileDownloader مالك النقل، MkvExporter مالك تحويل واحد؛ existing queue/manifest/sidecar/Room لا تزال مصادر recovery. لا نظامان يتنافسان. يمكن إنشاء ledger indexed تدريجي يتكامل مع Queue110 فقط بعد discovery/rollback؛ القرار النهائي storage backend بعد مراجعة schema. قبل أي تغيير schema اختر add-only/versioned migrations مع اختبارات upgrade/rollback؛ ممنوع destructive migration. 
2. Stable logical key: work/source namespace + stable episode ID + selected quality + output profile؛ account scope identity حين يلزم دون logging. season/episode labels display only؛ taskId signed int قد يكون صفراً أو سالباً، URL ليس المفتاح. generation/epoch يغير فقط عند intent change/retry ownership. Dedup key + batch request ID + native transfer ID mapping; duplicate callbacks no-op. Cancel tombstone persists, explicit re-enqueue creates new generation. 
3. Batch admission: UI snapshots selection (small immutable identities, no large bitmaps/context), commits batch header+items on I/O executor. Transaction ACK exact requested/accepted/already/failed/unavailable; retry idempotent batch_id. لا تظهر accepted قبل durable commit. إذا استخدم chunks 50–100 مع header durable يثبت full manifest، track partial ACK/resume; لا تقول accepted لكل الدفعة بعد أول chunk. On dismissal cancel optional UI previews فقط، committed work continues. Selection gaps 120/128/130 تظهر كغير متاحة بعد bounded source refresh؛ لا invent IDs أو تغيير الجودة. Resolve just-in-time and start ready items without barrier. Native bridge preserves required main entrypoints only; no main blocking I/O.
4. Task states: INTENT_SAVED -> RESOLVING -> READY -> NATIVE_SUBMITTING -> TRANSFERRING -> SOURCE_VERIFIED -> MUX_READY -> MUX_RUNNING -> OUTPUT_VERIFIED -> DB_COMMITTED -> DONE. WAIT_SERVICE / WAIT_NETWORK / WAIT_SUBTITLE / RETRY_AT / WAIT_STORAGE / PAUSED / CANCELED / NEEDS_ATTENTION carry reason and resume stage; no silent indefinite processing. Native callback not enough for source: identity, terminal byte proof, filesystem verification, exact subtitle dependencies. UI playback allowed for verified readable source if safe; state reflects failure reason if not. Output promotion: validate streams/path/identity, staged atomic move where possible -> verify DB path+size ACK -> cleanup source only if ownership/epoch+verified output; no remove on ambiguous state. 
5. Service connection state DISCONNECTED -> BINDING -> READY -> LOST/BACKOFF; actor/atomic single-flight, use monotonic deadlines, callback generation fencing, bindingResult accepted != READY; timeout -> bounded backoff+jitter (1/2/4/8/16/30s proposed), only schedule when work actionable. Native parallel config apply only after verified READY and confirm result; no reapply per task. Recovery read-only/DB receipts may proceed sans service only if proven safe. No fake service status or service restart after explicit force-stop until user opens app. 
6. Scheduler incremental: dirty ID set/coalesced events + bounded scan (start 16–32 candidates or ~20–50ms per worker tick as soft budget), cursor stable indexed ordering + periodic low-frequency audit only while work exists. No loops of repeated whole maps/Room builders. One deadline timer shared for retry/watchdog; no per-item Timer/Thread. Stop idle polling when no pending or due work. Fairness: old verified-ready first, waiting dependencies release worker and scheduled retry; interrupted valid stages use bounded priority, not starvation. UI control and playback get priority; separate queue/transfers vs mux, subtitles not starve video.
7. Adaptive capacity: shared metadata dispatcher 6 workers initially (evidence original 6 analyzed 496 in ~7.7s), experiment 8/12/16 only if throughput improves. Size previews lazy/cache TTL, optional 2; avoid HEAD/Range bulk before admission. Native video 2 initial, preserve user parallel settings as explicit max; adaptive pressure can lower new starts but never cancel active transfer solely for backlog. MKV 1 initial after DAO fix, test 2 only if single worker progresses and throughput/CPU/storage justify. Separate soft limits from durable queue size. No hard total thread cap for runtime-managed pools.
8. Backpressure with hysteresis proposed: high backlog of verified MP4 >=20 or oldest-ready age >=120s triggers reduce optional probes and new video starts; resume normal at <=8 and healthy consecutive samples. Use free storage reservation and low-memory signal, not RAM alone. Do not block all progress when malformed head item exists. Use user-visible reason, no automatic deletions. These are initial tunables not measured final thresholds.
9. Retry classification: 401/403 expired authorized access => refresh through existing authorized API once then classified retry; 404 candidate gone => re-resolve; 429/503 honor Retry-After/backoff; transient DNS/connection => network-aware retry; 416/validator mismatch => quarantine partial and restart only after verified source identity/explicit safe policy. 200 to requested range cannot append blindly; 206 Content-Range exact; unknown length not error by itself. Bound attempts per stage, retry later max interval, user-visible needs attention; preserve paused/canceled. Don't bypass authorization. 
10. Instrumentation: events batch_received, intent_committed, native_submit_requested, native_owned_ack, native_terminal, source_verified, mux_ready, mux_lease, mux_output_verified, db_committed, cleanup_done, blocked_reason, retry_scheduled, service state and DB owner creation. hashed/ephemeral identifiers, no raw URL/path/account; monotonic timestamps + wall metadata; duplicate counts separate from unique IDs. Progress sample 250–500ms UI aggregation, diagnostics bounded writer (optional overflow counter, no sync main fallback), durable critical state in journal not log.
