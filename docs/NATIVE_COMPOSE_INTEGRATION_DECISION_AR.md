## Preferred investigation: one package, explicit UI dependency isolation
- Existing owner, account, downloader, signing, media, files and original resource table remain untouched. Separate process alone does not isolate classes or resource IDs: same APK classes/resources are resolved from its installed package.
- Evaluate build-time namespace relocation/repackaging of the NEW UI dependency graph and UI-only generated resource names, before D8/AAPT packaging. Exact overlaps are only the first gate; include all references, hierarchy, annotations, Kotlin metadata, reflection/service-loader and Android manifest names. Avoid moving platform classes; never delete original AndroidX/Kotlin definitions. Reserve a non-conflicting UI namespace and retain original IDs in public.xml. A same-named resource is not proof that its value/style/attributes match. Build/verify RESOURCE_ID mapping; no blind literal rewriting. Must prove zero DEX definition overlaps, explicit runtime linkage and stable original resource IDs with signed APK and ART.
- Alternative custom classloader + separately packaged resources / isolated splits is research-only: parent lookup, split resource behavior, lifecycle/Context and Android API constraints must be experimentally proven. Do not assume a process or split automatically isolates duplicate classes.
- Separate UI APK companion is a lower-risk fallback for class/resource isolation; would require explicit user installation and separately authenticated signature-protected cross-package IPC, exact package/certificate pin and version pairing. Not selected for delivery without owner discussion; user requested one app. Never export current same-UID synthetic service as-is. No raw data or filesystem crossing.
- If neither single-package approach is stable, evaluate small native Views renderer with no overlapping dependencies; trade-off against Compose visual parity and development speed.
## Resource candidate audit
Read-only scan of original Smali integer field declarations and const instructions matching affected original public IDs; report path/line and both names. A numeric match is not evidence of actual resource access; no mutation, does not include XML/computed/array IDs or private resources. This prioritizes original-ID preservation.
