## Decision (provisional, not owner authorization to replace)
Android-only Kotlin Jetpack Compose is candidate for original UI; standard Android Views baseline may be easier to integrate into APKTool/Smali (no restored Gradle app, dependency and duplicate classes risk for Compose). Keep tested local HTML as reference/fallback, don't abandon it or migrate original runtime before comparison. Multiplatform only when another platform matters. Design tokens, navigation, screen semantics and bounded owner IPC are reusable for any renderer; native renderer can bypass JS transport and use same typed owner protocol, never independently query production Room from UI process. Keep 3 existing slots/Lease115, independent lifecycle, no synchronous IPC/DB/network/file/mux, latest state coalescing, stable row identities; prioritize measured bottlenecks. UI-only process must not run Dagger/LocalRuntime/Restart108; owner stays historical main. New pure UiProcessPolicy requires exact package+suffix API28+, denies new UI/owner read if unknown and preserves historical startup. Not wired to APK.
