## Source-level failure modes and changes
1. `MkvExporter.waitForCompletedVideoAndExport` ran on **the same single-worker JOB_EXECUTOR** used for ready recovered MKV. It could poll an unavailable or unsteady source for **120 seconds**. Enough such head-of-line jobs can delay ready E42/E49 despite queue promotion. PATCH328 bounds this pre-export callback wait to **15 seconds**; stable, valid sources still pass unchanged `waitAndExport` and `Inputs114`/Room/manifest gates. Timeouts retain source, subtitles, recovery and native receipts; the existing 1.5s guarded reconciler and startup/manual repair reschedule later when eligible. This is a code-confirmed throughput bottleneck, but whether it was the specific E42/E49 blocker requires fresh runtime traces.
2. `MkvExporter.exportLocked` uses synchronous `InputStream.read` and `Process.waitFor()` on the native FFmpeg process, **without an intrinsic hang timeout**. A child which leaves its pipe open but stops writing can block the single mux worker indefinitely. PATCH328 adds one **daemon, MIN_PRIORITY, non-UI** `MkvProcessGuard328` monitor per FFmpeg spawn. It samples only the app-owned leased `.mkv.cnm115-UUID.part` file's length every 5s using elapsed realtime. If **no byte-size change for 120 seconds** and the child remains alive, it logs `PATCH328_FFMPEG_STALL no_stage_progress_ms=`, calls process `destroy()`, then escalates via `destroyForcibly()` if still running. It never deletes/renames/edits files or touches Room/manifest state. The original exporter error/finally path releases its singleton permit and lease; subsequent guarded repair can rebuild from complete MP4. Avoid declaring native hangs as proven until a fresh watchdog log and process details exist. A 120s no-progress threshold balances safety vs. avoiding slow device false positives.
3. `MkvExporter.queueTelemetry()` reads ThreadPoolExecutor queue depth and active worker count, without modifying the queue. `DownloadRepair129.prioritizeInterruptedParts` appends `queue_depth=N active_workers=M` only at startup/manual staged priority audit, enabling future distinction among queue starvation, an occupied exporter, or stalled recovery.
4. Preserve PATCH326 lease-only obsolete-stage cleanup, PATCH327 busy-state write exception protections, one worker, one `FFMPEG_SLOTS` permit, MP4/metadata, native parallel downloads, exact subtitles/Room and original player navigation. **No deletion of MP4, subtitle, sidecars or app data is part of PATCH328.**
